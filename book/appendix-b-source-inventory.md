## Evidence from tests and benchmarks

The repository's CI runs ordinary/race tests, Rust-module checks, privileged Linux tests, and a runtime/dataplane/preview matrix. AgentGateway's lane has different gating semantics from the principal lane. [The workflow](https://github.com/agent-substrate/substrate/blob/v1.0.0/.github/workflows/pr-workflow.yaml) is evidence of intended validation coverage, not evidence that this checkout passed that coverage while the book was written.

The [tunnel harness](https://github.com/agent-substrate/substrate/blob/v1.0.0/benchmarking/atunnel/README.md) exercises real atunnel and namespace behavior while replacing other components. The [Nighthawk ingress harness](https://github.com/agent-substrate/substrate/blob/v1.0.0/benchmarking/nighthawk-ingress/README.md) uses an adaptive mean-plus-two-standard-deviations criterion that must not be relabeled as p95. [Phase analysis](https://github.com/agent-substrate/substrate/blob/v1.0.0/benchmarking/analysis/phase_report.py) joins node and runtime records; overlapping phases cannot simply be added. These distinctions determine which production claims a measurement can support.

## Runtime provenance

The gVisor [SandboxConfig](https://github.com/agent-substrate/substrate/blob/v1.0.0/manifests/ate-install/sandboxconfig-gvisor.yaml) default version `v7` pins release `20261102.0`, and version `v6` (`20261026.0`) stays enabled for memory snapshots taken on it. Each has per-architecture digests. The installer [microVM asset code](https://github.com/agent-substrate/substrate/blob/v1.0.0/cmd/ate-setup/internal/steps/microvm.go) defaults to Kata `4.3.1` and Cloud Hypervisor `v53.0`. The copied Kata message definitions document their own upstream provenance and compatibility check; they are not a vendored full Kata runtime.

RustFS is pinned to `1.0.3` by digest in the local manifest. The exact storage semantics relevant to Substrate include object writes, reads and ranges, prefix copy/delete, multipart behavior, error handling, and restart persistence. A successful bucket creation proves only one small part of that contract. The book treats the repository integration as evidence of the chosen backend path and calls for workload-specific validation before assigning a production durability objective to it.
